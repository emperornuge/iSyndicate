# Mob Empire (working title)

A multiplayer mobile crime-empire game in the spirit of classic Storm8's iMobsters —
missions, PvP fight arena, equipment shop, real-estate income, mob invites, bank,
hospital. iOS app built with Capacitor; authoritative game server in Node/Express
with SQLite persistence.

> **Name is a placeholder.** "iMobsters" is Storm8's trademark and can't ship.
> Rename in `capacitor.config.js` (`appName`, `appId`), the App Store Connect
> record, and the workflow's bundle-ID comment before submitting for review.

## Layout

```
server/          Game API (Express + node:sqlite). Deploys to Fly.io.
  src/index.js   App bootstrap
  src/routes.js  All /api endpoints (login, missions, shop, bank, fight, mob, hospital)
  src/game.js    Missions/items/real-estate catalogs, combat math, tick loop
  src/db.js      SQLite persistence (WAL mode, DATA_DIR configurable)
  Dockerfile     Production image
  fly.toml       Fly.io app config (shared VM + 1GB volume, ~$5/mo)
client/          React game UI, bundled by Vite into static assets (no CDNs).
  src/App.jsx    The whole game UI (Jobs / Fight / Shop / Mob / Vault tabs)
  src/api.js     API client; base URL comes from VITE_API_URL at build time
ios/             Capacitor iOS shell (generated by `npx cap add ios`, committed).
assets/          App icon source (1024px) + generated iOS icon set.
.github/workflows/ios-testflight.yml
                 macOS CI: build web bundle -> cap sync -> xcodebuild archive ->
                 export + upload straight to TestFlight. Runs on every push to main.
metadata/        App Store listing draft + review notes.
```

## Local development

```bash
npm install

# Terminal 1: game server (http://localhost:3000, data in server/data/)
npm run dev:server

# Terminal 2: web UI with /api proxied to the server
cd client && npx vite
# -> http://localhost:5173
```

## Deploy the game server (do once)

```bash
# needs the fly CLI: https://fly.io/docs/hands-on/install-flyctl/
cd server
fly launch --no-deploy        # accept the generated name, e.g. mob-empire-api
fly volumes create mob_empire_data --size 1 --region iad
fly deploy
fly open                      # note the https URL, e.g. https://mob-empire-api.fly.dev
```

That URL becomes the `API_URL` GitHub secret. The iOS app talks to it for
everything; the tick loop (energy/stamina/health regen, real-estate payouts)
runs server-side.

## Ship to the App Store (the only manual steps, all yours)

1. **Enroll** in the Apple Developer Program ($99/yr) — tied to your identity,
   can't be delegated.
2. **App Store Connect**: create an API key (App Manager role). Save the
   Issuer ID, Key ID, and the .p8 (downloaded once).
3. **Register the bundle ID** `com.mobempire.game`, then create the app record.
4. **Create a GitHub repo**, push this project, add the five secrets
   (`API_URL`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_PRIVATE_KEY`, `TEAM_ID`).
5. Push to `main` -> the workflow builds, signs, and uploads to TestFlight
   automatically. Install via TestFlight, then **submit for review** in
   App Store Connect when ready.

After that, every push to `main` ships a new TestFlight build with an
auto-incremented build number. No Mac required on your end, ever.

## Notes

- Accounts are username-only (classic Storm8 style) — no passwords, no PII.
  Usernames are stored server-side; sessions persist in the app via localStorage.
- Privacy manifest (`ios/App/App/PrivacyInfo.xcprivacy`) declares the alias as
  a linked user ID used for app functionality, no tracking.
- Expect a **17+ age rating** (crime/violence themes) at review.
- The three seeded bots (Don_Corleone, Scarface_Tony, Soprano_Tony) give day-one
  players fight targets and mob codes before real players arrive.
